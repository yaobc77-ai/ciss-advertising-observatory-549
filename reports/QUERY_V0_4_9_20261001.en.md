# Query record browsing 0.4.9

The earlier Query page showed only ten records behind a statistics answer. Its link opened Data without the answer's selection. This update replaces that link with **Inspect matching records**, including Previous, Next and First page controls.

Paging keeps the complete submitted selection, including dates, unknown-date policy, historical labels and record subsets. It browses the percentage numerator, with native and social records kept separate. Editing the composer does not change saved results. Paging reads the database and does not call a model.

Both question routes bind statistics to a server-checked source version. Each page checks that version and the matching total before displaying rows. An unavailable source can be retried; a changed source or an unverified saved selection requires a new query. Model interpretation of a submitted question can still incur its existing API cost.
